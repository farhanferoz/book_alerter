### Phase 3 — Scheduler

- **Task 3.1** — `b91681c` `Scheduler` (in `src/book_alerter/scheduler.py`) wraps APScheduler's `AsyncIOScheduler`. Registers one cron job per enabled source from `config.sources` (`id="source:{name}"`, `jitter=jitter_seconds`, `max_instances=1`, `coalesce=True`). `_run_source` writes a `SourceRun` audit row, gathers `select(Book).where(status="active")`, fans out per-book fetches under a `Semaphore(concurrency)` with `per_book_delay_seconds` jitter, persists `PriceObservation` rows, updates the `SourceRun` status (success / partial / error), tracks consecutive errors with exponential backoff capped at 24 h, and calls `alert_pipeline(affected_book_ids)`. `app.py` lifespan now builds `engine`, `build_sources(cfg)`, the scheduler, starts it on enter and `shutdown(wait=False)` + `engine.dispose()` on exit. 3 unit tests (`test_scheduler_registers_jobs_from_config`, `_no_jobs_when_source_disabled`, `_skips_unknown_source_in_config`); 31/31 passing.
  - **Fix beyond plan**: captured `run_id: int = run.id or 0` immediately after `session.refresh(run)` because SQLModel `Session(expire_on_commit=True)` would later try to refresh `.id` on a closed session. The plan's `return run.id or 0` at the bottom would have failed; the fix keeps `run_id` available across session boundaries.
  - **Test deviation**: the plan's snippet uses sync `def test_…`, but `AsyncIOScheduler.start()` requires a running event loop. Tests converted to `async def`; `pytest-asyncio` is in auto mode, so this Just Works.
  - **Hoists**: `from sqlmodel import select` and `from datetime import timedelta` lifted to module top (plan had them as inline imports).
