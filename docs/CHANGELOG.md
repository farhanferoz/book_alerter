## 2026-05-14

### Phase 1 — Data model

- **Task 1.1** — `01dad29` Book table + Alembic migration `0001_book_table.py`. All spec fields present (isbn13 unique+indexed; format/status enums; JSON `alert_kinds_disabled`; nullable `target_price_minor`, `percentile_threshold`, `bought_price_minor`, `muted_until`, `notes`, `cover_url`; defaults `region=UK`, `currency=GBP`, `format=any`, `status=active`). 8/8 tests passing.
  - **Deviation (forced)**: `Literal[...]` SQLModel fields require `sa_column=Column(String, nullable=False)` because SQLModel 0.0.22's `get_sqlalchemy_type` calls `issubclass(Literal, Enum)` and raises `TypeError`. Python-level `Literal` annotation preserved (validation still works); column stored as `String`. Applied to `format` and `status` only.
- **Tooling fix** — `17379f8` Added `render_item` hook in `migrations/env.py` so autogenerated migrations auto-include `import sqlmodel` whenever a SQLModel column type (e.g. `AutoString`) is rendered. Without this, every autogen migration needs a manual import added or fails with `NameError`. Discovered while completing Task 1.1; applied immediately so Tasks 1.2–1.4 don't have to redo the workaround.
- **Task 1.2** — `cd2ac35` PriceObservation table + migration `0002_price_observation.py`. Self-FK `is_duplicate_of → priceobservation.id`; FK to `book.id`; composite indexes `ix_obs_book_observed` (book_id, observed_at) and `ix_obs_book_source_observed` (book_id, source, observed_at); raw JSON column for source payload. Same `Literal` → `sa_column=Column(String)` pattern for `condition`. 9/9 tests passing. No design deviations.
- **Task 1.3** — `7a9fdec` SourceRun + Alert + NotificationDelivery + BookSignalState tables in migration `0003_source_run_alert_delivery.py`. BookSignalState shipped here despite the filename (per plan line 1125). Four round-trip tests added; 13/13 tests passing.
  - **Process note**: autogen failed initially with "Target database is not up to date" because `data/book_alerter.db` had only the 0001 migration applied. Two recovery paths: (a) `uv run alembic upgrade head` against the dev DB before autogen — used by the orchestrator between Task 1.3 and 1.4; (b) autogen against a temp DB brought to head first — used by the 1.3 implementer. The dev DB is now at HEAD; future autogens should run cleanly. **Convention going forward**: after each migration task, run `uv run alembic upgrade head` so the dev DB tracks the latest revision.
- **Task 1.4** — `cfcb955` `book_stats` read-only SQL view in migration `0004_book_stats_view.py`. Raw DDL (no autogenerate). Exposes per-book `current_best_*` (latest-per-source, then min total, deterministic tie-break by source name), `all_time_min/max_total_minor`, `observation_count`, `last_observed_at`, `days_of_history`. Percentiles deliberately deferred to Python (`compute_book_stats()` in Phase 4). Test uses real `alembic upgrade head` against a `tmp_path` DB; 14/14 tests passing.
